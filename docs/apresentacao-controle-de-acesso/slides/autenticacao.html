Autenticação: o token só identifica

1

POST /auth/dev-login emite o JWT, em lugar do gateway dos agentes

2

O front envia Authorization: Bearer em toda chamada

3

O middleware valida e sobrescreve o user_id da query e do corpo JSON

4

SSE: EventSource não envia headers, então o token vai em ?access_token=

Autenticação simulada: não há senha nem login real. Quem chamar o dev-login com um usuário do acl.yml recebe o token dele.

JWT · HS256 · 8 h

{
  "id": "321",
  "email": "bruno@…",
  "name": "Bruno Colaborador",
  "iat": …, "exp": …
}

Sem role no token. O papel é consultado no servidor a cada requisição: mudar o papel vale na hora.

O dev-login não pede senha e não prova quem a pessoa é: ele ocupa o lugar do gateway na POC. O token garante que qualquer alteração depois de emitido invalida a assinatura e a requisição é rejeitada. Em produção o token vem do gateway real e esse endpoint some. Sem AUTH_SECRET no ambiente a POC usa um segredo fixo de desenvolvimento.

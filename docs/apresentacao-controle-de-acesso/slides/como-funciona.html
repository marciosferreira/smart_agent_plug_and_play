Como é feito, em código

graphql_config.run_query_table (simplificado)

pol = politica_para(user_id)
# 1. no pedido: valida e soma o filtro
where = pol.preparar_tabela(
  table, where, order_by, expand)
data = _post(query, variables)
# 2. na resposta: apaga colunas negadas
return pol.limpar_linhas(
  table, data["reportTable"])

O LLM pede

where site_id = 7

Vai ao backend

where site_id = 7 AND is_forecast = false

O backend devolve

site_id, rate, approved_at

O LLM recebe

site_id, rate

Exemplo para o papel colaborador; site_id e rate são ilustrativas, approved_at e is_forecast vêm do acl.yml

O código real está em graphql_config.run_query_table e run_aggregate. Em preparar_tabela a política recusa o que não é permitido (AcessoNegado) e devolve o where com o filtro do papel somado em AND. Em limpar_linhas ela percorre as linhas devolvidas e apaga as colunas negadas, inclusive as vindas de expand. Os nomes site_id e rate do exemplo são ilustrativos.

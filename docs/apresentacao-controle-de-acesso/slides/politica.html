O acl.yml define o que cada papel consulta

gerente:
  tables:
    fact_hourly_rate: {}
    fact_dl_discount: {}
    fact_final_dl_cost: {}
    ...

Gerente: as tabelas listadas, sem restrição de coluna nem de linha. Tabela fora da lista é recusada.

colaborador:
  tables:
    fact_hourly_rate:
      columns: {deny: [approved_at]}
      rows:
        - {field: is_forecast,
          op: EQ, value: false}
    dim_site: {}
    ...

deny: coluna barrada no pedido e apagada da resposta. rows: só as linhas que cumprem a condição (aqui, is_forecast = false). São independentes. dim_site: {} é liberada por inteiro. Só as tabelas listadas valem.

Recusa: o colaborador consulta fact_dl_discount e o LLM recebe Acesso negado: o papel 'colaborador' não tem acesso à tabela 'fact_dl_discount'. O gerente consulta normalmente.

Trechos reais do config/new_age/acl.yml, simplificados: as reticências indicam outras tabelas na lista (no arquivo real o gerente tem 10, entre dimensões e fatos; o colaborador também tem outras além das mostradas). O tables é uma allowlist: só as tabelas declaradas podem ser consultadas e as demais somem também do schema que o LLM vê. O arquivo tem três partes: users (user_id → papel; é a tabela user_role da POC), roles (as regras de cada papel) e relations (chaves estrangeiras, usadas para validar o expand; sem a relação declarada o expand é negado, e também é negado para tabelas com restrição de linhas). Papéis: admin (tables: "*", tudo), gerente (todo o custo), colaborador (o custo com as restrições acima) e consulta_basica (só as dimensões, com allow: [id, name, country, status] em dim_site). O nome do papel não tem relação com os agentes do sistema, como o agente analista. rows é uma condição somada em AND ao where do usuário: o usuário ainda filtra por outras colunas, e se pedir is_forecast = true o resultado vem vazio (não é recusado). Vários itens em rows entram todos em AND. columns (deny ou allow) e rows são chaves independentes: uma tabela pode ter só deny, só allow, só rows ou combinações; sem columns nenhuma coluna é bloqueada e sem rows nenhuma linha é filtrada. As regras não foram conferidas contra os dados reais.
